# Issues found, and what was done

*AI-to-learner knowledge transfer study (ECG age). Author: KEYUR SHAILESHKUMAR PATEL (ORCID https://orcid.org/0009-0008-5261-043X).*

Every problem found in the code or design, how it was found, how serious it was, and the fix. Problems are never deleted from this list.

| # | Found | How found | Problem | Severity | Fix | Status |
| --- | --- | --- | --- | --- | --- | --- |
| P1 | v0.1 review, 2026-11-03 | Re-reading the split code against the PTB-XL paper | A patient could be in two roles: the held-out device role took ECGs from any fold, and the early-stopping split was by ECG, not by patient. Information about one patient could reach both the AI and the tests. | High (leakage) | Roles by patient; validation patients chosen by a fixed SHA-256 rule; other-device ECGs of transfer patients set aside. Self-check C1 stops the run if any patient is shared. | Fixed in 0.2.0 |
| P2 | v0.1 review | Same | One learner's tests could contain two ECGs of the same patient, so items were not independent. | Medium | Each learner's practice and test sets use one ECG per patient, and the pre, post and delayed tests use different patients. Self-check C4. | Fixed in 0.2.0 |
| P3 | v0.1 smoke run | Analysis warning: zero variance | Experiment B's no-training nets were untrained, so all gave identical answers and H2/H3 were undefined. | Medium | No-training nets practise on the same ECGs with shuffled labels (same compute, no real feedback). | Fixed in 0.2.0 |
| P4 | v0.1 review | Thinking about what the Welch test assumes | Learners draw test ECGs from a shared pool, so their scores are not fully independent. | Low to medium | Item-level regression with two-way cluster-robust errors (learner and ECG) reported as robustness. The synthetic validation checks how both tests behave when learners share ECGs. | Fixed in 0.2.0 |
| P5 | v0.2 smoke run, 2026-11-03 | Self-check C11 failed | Which letter means "older" was a coin flip per learner, so a group could get an uneven mix (seen: 67% vs 33% with 6 learners). | Low at full size, but avoidable | Letters alternate per learner: exactly balanced within each model and group. C11 now requires this. | Fixed in 0.2.0 |
| P6 | v0.2 build | Code review while writing scripts/pin_models.py | The config had a place for exact model commits, but the language-model loader ignored it. Models could silently change between runs. | Medium (reproducibility) | Loader now uses the pinned commit and logs it; an unpinned confirmatory run is listed as a deviation. | Fixed in 0.2.0 |
| P7 | v0.2 build | Environment check | `wfdb` (reads PTB-XL signals) was listed in requirements.txt but not in the exact-version list. | Low | Added to requirements.lock. | Fixed in 0.2.0 |
| P8 | Validation dry run (quick), 2026-11-03 | Tamper test: `verify` reported a change before anything was tampered with | The last log line ("done") was written to run.log after run.log had been hashed, so every finished run failed `verify` on run.log. | Medium (a false alarm on every run) | Log the last line, flush, then hash. The validation's tamper test now passes before tampering, catches a one-byte change, and passes again after restoring. | Fixed in 0.2.0 |
| P9 | Validation dry run (full size), 2026-11-03 | W1 and W3 expectations not met | In the "informative" world the planted lesson effect was +2.2 points (W1) and +2.0 points (W3 blinded), below the 3-point bar, because the mock learners already reach about 83% from 30 practice cases. The H1 rule correctly said "significant but below the meaningful threshold". The advance expectation ("H1 supported") was set too high. | None for the software; informative for the design | Expectations kept as written and reported as not met, with the reason. Added world W1b (learners that lean on written rules) with its expectation stated before it ran. The author had already confirmed the 3-point bar after seeing the power simulation (decision D6), before this result. | Explained; kept in the record |
| P10 | Final validation, 2026-11-03 | W1b expectations not met | W1b's planted gain was only +1.4 points (main) and +0.9 (blinded): leaning on rules cannot beat the rules' own ceiling (about 85% on the fake data), and practice alone already reaches 83%. Again the rule correctly said "significant but below the bar". | None for the software | Kept as a miss with its reason. No further worlds were tuned, to avoid adjusting the test until it passes. That the pipeline finds large effects is shown by H7 (+30 to +37 points, supported in every world with signal) and by the power simulation. | Explained; kept in the record |
| P11 | Real-data pilot, 2026-11-07 | Two pilot runs with the same seed and data gave different teachers (AUROC 0.987 vs 0.989) and different cues (5 vs 8). Traced to the input scaling. | The per-lead mean and SD were summed in float32 over about 5 million values. The result depended on how the array sat in memory: a fresh read from the WFDB files and the cached .npy copy (identical values) gave SDs 0.5% apart. So the first run on a new machine differed from every later one. | High (reproducibility of the treatment itself) | Scaling now summed in float64; fresh and cached reads give identical results bit for bit (new test). | Fixed in 0.3.0 |
| P12 | Real-data pilot | Running the documented step `check-data` on a fresh folder | `check-data` failed with "ptbxl_database.csv not found" because it did not download or unpack PTB-XL first. | Low (usability) | `check-data` now downloads and unpacks if needed, then verifies. | Fixed in 0.3.0 |
| P13 | Real-data pilot | The cloud machine restarted during the v0.2 Qwen run | Learner results were saved only every 25 learners, so 20 finished learners (about 3.5 hours) were lost. | Medium (lost compute; `--resume` could only restart from the last save) | Results are saved after every learner (items file first, then the learner file that `--resume` reads). | Fixed in 0.3.0 |
| P14 | Real-data pilot | Reading the pilot's cue report | The cue rule (sparsest C with at least 5 stable features) jumps between settings: with one teacher C=0.01 gave 5 cues, with a nearly identical teacher it gave 4, so the rule moved to C=0.05 and took 8. | High (design) | Author's decision D9: consensus across 5 teacher seeds. On the pilot folds, 4 cues were chosen by all 5 teachers (PR interval, T-wave height II, QRS axis, R-wave height aVL) and 2 by 3 of 5 (QTc, S-wave depth V1); all 5 teachers agree on every direction. Self-check C16 recounts the votes. | Fixed in 0.3.0 |
| P15 | Real-data pilot | Cue report: scrambled-rule accuracy | The placebo lesson, applied as written, scored 36% (v0.3 cue set) and 46-54% in other draws: random directions can point the wrong way, so the placebo could teach the opposite. That would inflate H7. | Medium (design) | Decision D10 (author, 2026-11-08): re-draw with a fixed seed until the placebo tally scores 45-55% on the cue fold. On the pilot folds: draw 5, 46% cue fold, 47% learners' test pool. Self-check C17. | Fixed in 0.3.0 |
| P16 | Real-data pilot | Experiment B results | Feedback-only nets reach about 81% from 64 practice ECGs; cue training adds +0.2 points (v0.2 cues, 30 per group). Same ceiling as synthetic world W1 (P9). | None for the software; informative for the design | Reported. Whether to change Experiment B (for example fewer practice ECGs) is the author's call before preregistering. | Decided 2026-11-14 (D13): Experiment B stays as designed but becomes secondary. Follow-up sweep 2026-11-14 (4 to 128 practice ECGs, 30 nets per group): the cues add nothing at any practice size and the scrambled cues do as well, so it is not a ceiling; see `pilot/PILOT_FOLLOWUP.md` |
| P17 | Real-data pilot, 2026-11-07 | The v0.3 Qwen run was killed by the system (out of memory, 13.9 GB) when the feedback group started | Feedback and cue prompts are about 9-12k tokens (numbers tokenise into many tokens). One forward pass over the shared prompt built full attention matrices (about 16 x 11k x 11k) and full-vocabulary logits for every prompt position. The same code would likely also fail on a 12 GB GPU. | High (the language-model experiment could not run) | The shared prompt is fed in chunks of 2,048 tokens into the cache (same computation, bounded memory); only the last position's logits are computed (`logits_to_keep=1`). Check on a 3.9k-token prompt: one pass 0.9841, chunks of 1,024 0.9831, chunks of 256 0.9820, plain full pass 0.9850 (bfloat16 rounding; well inside the 0.02 tolerance of the built-in check). At about 11k tokens bfloat16 differences reach about 0.05, so for very long prompts p(older) is precise to a few hundredths; answers are scored by the larger probability, which such differences rarely change. | Fixed in 0.3.0 |
| P18 | Real-data pilot, 2026-11-08 | Second out-of-memory kill (13.9 GB) after 40 more learners, early in the cue group | After P17, the suffix batch still copied the prompt's cache 8 times (8 x about 0.4 GB at 10-12k tokens), on top of the weights (6 GB) and the prefill's attention buffers. | High (the run could not finish) | The number of rows per suffix batch is now capped by a memory budget (default 1.5 GB for cache copies, `AI2HUMAN_KV_BUDGET_GB`); prefill chunks are 1,024 tokens (`AI2HUMAN_PREFILL_CHUNK`); buffers are freed after each prompt. Same computation, smaller batches. | Fixed in 0.3.0 |
| P19 | Real-data pilot, 2026-11-08 to 2026-11-12 | Experiment A results: every group near 50% by accuracy; 69% of Qwen2.5-3B learners gave nearly one answer on the post-test | Letter bias: on long real prompts the model answers almost only "A" or only "B". Letters are balanced across learners, so the bias favours no group, but it pushes accuracy (threshold P(older) > 0.5) to chance and the collapse rule marks the model uninformative. The probabilities underneath do rank the ECGs after training: scored at each learner's own median (chance 50%), the main run gives no training 49.9%, scrambled 58.7%, AI cues 65.3%, feedback only 69.2%; per-learner AUROC 0.47, 0.62, 0.71, 0.74. These scores were chosen after seeing the data. | High (design: the planned primary outcome could not have shown an effect with this model) | Reported in `pilot/EXPLORATORY_PILOT_REPORT.md`. The outcome measure and the collapse rule for the preregistration are the author's decision. | Decided 2026-11-14 (D12): bias-corrected accuracy is the primary score; built into 0.4.0. Flat rule in place of the collapse rule confirmed 2026-11-14 (D15) |
| P20 | Real-data pilot | Reading `gate_llm.json` | The prior-knowledge probe answered "higher in older adults" for 17 of 18 measurements with probability above 0.9999 (only heart rate "lower"). This looks like the same answer bias, so the probe as written does not measure what the model knows. | Low | Each question is asked twice with the letters swapped; a direction counts as known only if both agree (decision D18). | Fixed in 0.5.1 |
| P21 | Real-data pilot | Timing the runs | README run-time estimates were guesses. Measured on 4 CPU cores (no GPU): teacher about 5 minutes each; Experiment B about 5 seconds per net; Qwen2.5-3B about 3 minutes per no-training learner and about 11 minutes per learner with a lesson (prompts of 9-12k tokens). The cloud machine also restarted repeatedly; the v0.3 pilot needed many resumes. | Low | README shows the measured times. A GPU is needed for the full study. | Fixed in 0.3.0 (documentation) |
| P22 | Real-data pilot | Reading `cohort.py` while writing the disclosure | In `--pilot` mode the seal is applied after the PTB-XL+ feature table has been loaded whole. Two steps therefore run over all rows, sealed ones included: the unit check (median absolute value of each amplitude measurement, to tell millivolts from microvolts) and the count of missing panel values that defines an eligible ECG (used to pick the sealed device). Neither relates age to any ECG feature; no sealed ECG signal is read and no sealed row is written to any output. | Low | None in code: the pilot is finished and the confirmatory run does not use pilot mode. Stated exactly in `prereg/PILOT_DISCLOSURE.md` section 2. | Disclosed |
| P23 | Follow-up to the pilot, 2026-11-14 | Counting distinct probabilities per learner while building the bias-corrected score | In bfloat16 the model's own logits have about 8 significant bits, so the 40 answers of a test fell on about 13 distinct probabilities; on average 12% of a learner's items tied at its median, and the tie rate differed by group (post-test, main run: feedback only 6.5%, AI cues 11.6%, scrambled 16.5%). Ties get half credit, so part of the pilot's gap between feedback and cues may be an artefact. | High for the bias-corrected score | The two answer letters are re-read in float32 from the last hidden state (`experiment_llm.answer_precision: float32`); the model's own logits are kept as a check (Qwen2.5-3B: largest difference 0.124). Rounding noise inside the bfloat16 model remains (up to 0.06 in probability between two ways of reading the same prompt); a float32 run on a GPU would remove it. | Fixed in 0.4.0 (read-out). Decided 2026-11-20 (D17): the confirmatory run stays in bfloat16 with the float32 read-out |
| P24 | Repeating the synthetic validation on 0.5.1, 2026-11-20 | The validation was stopped after 2 hours still inside its first world | The P13 fix rewrote the whole learner and item files after every learner. With fast mock learners (1,002 per group) this made the run quadratic in the number of learners. | Medium (time only; results unaffected) | Checkpoint at most every 30 seconds (`experiment_llm.checkpoint_seconds`) and after the last learner. A real model takes minutes per learner, so it still saves after every learner. | Fixed in 0.5.2 |

The plan-vs-code audit did not check this sentence. | Low (wording only; the code and the other sections were right) | Changed to "the gate and flat rules" and re-frozen as 1.0.1 before OSF submission (D20). | Fixed in 1.0.1 |
